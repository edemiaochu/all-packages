## 数据与结论

- szewtwins-client：pnpm **12.9.1**，supply-chain 校验 795 entries；esbuild 因 overrides 生效从 0.21.5 → **0.28.2**（证明此前 package.json 里的 overrides 完全没生效）
- imodel-transformer：pnpm **11.9.0**（allowBuilds 在 11/12 均生效），supply-chain 校验 999 entries
- pnpm 12 构建批准配置：`allowBuilds`（map：包名 → true/false）取代旧键 `onlyBuiltDependencies`（列表）；旧键被**静默忽略**——无弃用警告、`pnpm config list` 照常显示、install 不认（结论从 pnpm.exe 二进制内嵌 hint 文案确认，网上资料尚未跟上）
- display-test-app：6 文件（5 改 1 新建），`rushx build` exit 0，产物 `lib/backend/CreateNewIVaultImpl.js` 等已生成
- 设计要点：采用**修订版**设计——初版（plan 文档）创建的文件因无默认 model/category 且前端无 editorToolSettings 默认值，编辑工具无法启动；修订版在后端插入默认内容并把 id 回传前端回填，`svt place line string` 等工具开箱即用
- 实现前核对的 API 事实：`insert()` 静态方法均提供 `EditTxn | IVaultDb` 重载；`withEditTxn` 定义于 `core/backend/src/EditTxn.ts:670`；`IVault.dictionaryId`（0x10）/`rootSubjectId`（0x1）为静态只读、经类继承可从 `IVaultDb` 访问；`BriefcaseConnection.openStandalone` 第三参有默认值 `OpenMode.ReadWrite`

## 问题与解决

- pnpm 12 静默废弃 `onlyBuiltDependencies` → 从 pnpm.exe 字符串表抠出 hint 文案（"add its name to allowBuilds and set to true"），确认新键名与格式
- `package.json` 的 `pnpm` 字段（含 `pnpm.overrides`）不再读取 → 迁到 `pnpm-workspace.yaml` 顶层 `overrides:`
- 改名流程在 allowBuilds 留下人读占位符字符串 → YAML 视为非 `true` → pnpm 判"未批准"；教训：机器读的配置里不能留人话占位符
- 本地 verdaccio（localhost:4873）单请求 10~60s 的大量 `[WARN] Request took` 只是慢不是错，排查时先排除这类噪声
- display-test-app 三份规划文档版本不一致（plan=初版、design=含修订、changes=最终版）→ 以含"验证记录"的 changes 文档为准实现，避免复刻初版"文件不可编辑"的坑
- 文档代码块里的 `["bim","ibim"]` 保存 filter 是改名残留，与 `.dtw` 默认文件名矛盾 → 实现改用 `["dtw"]`
