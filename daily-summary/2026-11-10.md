## 问题与解决

- 整标识符排除会误伤：`szewEC_ECClass` 里有真实 EC token，跳过整个标识符会漏替换 → 改为区间保护，只跳过落在保护串内部的命中
- `hideProduced` 只保护本次运行产出的替换串：源码里上一批已替换的 `szewec` 不在 `produced` 里，后续 EC 规则仍会改写 → 生成前先把基础替换词整体遮罩
- 遮罩会影响排除逻辑：`excludeSet.has(id)` 依赖原始值，若把排除项也遮罩会失效 → 对 exclude-list 中的标识符不做遮罩
- 不能在 `apply-replace` 阶段拦截：60 个「混合标识符」映射 key 会被遮罩切碎导致漏替换 → 保护只放在提取和生成阶段，替换期仍只由 `exclude-list.json` 做字面量占位符保护
- 保护词若也做成「生成一份再读取」的文件会出现两个真相来源 → 改为从既有替换配置推导，`--out` 只导出快照、不参与运行
- `--fused` 分支返回的 `matchedToken` 是 `lower`（既有行为）→ 保护判断按「该 token 的所有出现位置是否都在保护串内」处理，可正确跳过
- Windows 下 `du` / `find` 在大仓库上超时（>120s）→ 改用 `git status` 和直接读取目标文件收集材料
