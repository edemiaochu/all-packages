## 问题与解决

- Windows 改名规则：**打开句柄在子孙目录上也会阻塞祖先目录改名**，即使该句柄 `share` 包含 `FILE_SHARE_DELETE` → 必须放到句柄所在的那一层
- Restart Manager（`RmGetList`）对**目录**句柄完全无感 → 排查目录占用只能靠 `handle64.exe` 或 Process Monitor
- `MoveFileEx` 与句柄版 `SetFileInformationByHandle(FileRenameInfo)` 报同一个错（Win32 错误码 5），排除 API 差异
- `wmic` 在 Win11 26200 已移除、`fltmc filters` / `Get-MpPreference` 需管理员 → 诊断脚本一律走临时 `.ps1`
- 两阶段改名设计：批次内只改叶子，祖先目录靠最终全量补扫；任何中途失败都会让磁盘与配置停在中间状态
- `--no-clear-rush` 只是不清空 rush.json，条目仍只从本次 targets 重新累积 → 未被覆盖的包会消失（display-test-app 即如此）
- 仓库根级共享配置（`.mocharc.jsonc`）不在任何 target 子目录内，内容替换永远扫不到 → 11 个包 reporter 失败
- 多词映射是链式应用的，后一个词会改写前一个词的输出（`szewEC` 里的 `EC` 被 EC 规则改成 `DM`），短词 camel token 匹配是直接触发点
- `CorEcA` 属于另一类问题：它是 `CoreCA` 的随机大小写变体，被 EC 规则当原始 token 命中，占位符保护不覆盖这种情况，需加入 exclude-list
