00 · 整体认识

替换流程总览

工具链只做一件事：把源码里的品牌词 / EC 词换成新词。 提取 → 合并 → 配置映射 → 替换，前三步只产生 JSON，真正的源码修改发生在最后。

01提取敏感词search-sensitive
02提取 ECsearch-ec
03合并词表merge-ids
04配置映射replace-server
05合并映射merge-mapping
06bim 词族replace-bim
07执行替换replace-staged
点任意阶段可跳转到对应说明；点「播放流程演示」按顺序浏览。
安全底线（务必先讲给学员） 执行替换前先 git commit 或 git stash；每次正式执行前先跑 --dry-run 预览。没有版本控制兜底时不要执行最后一阶段。

两套用法

快速方式（一键启动）

适合第一次上手 / 演示。

  • 自动执行搜索、合并，并打开配置网页
  • 停在「配置映射」，不替你保存、不执行替换
  • 生成结果固定写在仓库根目录

完整流程（分步执行）

适合正式替换 / 需要自定义参数。

  • 每一步都能单独运行、复用已有结果
  • 可指定目录、词表、输出文件、批次
  • 可分阶段替换、构建、发包、测试
01 · 快速方式

一键启动：搜索 → 合并 → 打开配置界面

默认扫描整个仓库，敏感词表用 base-words.json， 生成 result.json、ec-result.json、all-ids.json， 然后启动配置网页并自动打开浏览器。

bash
node name-replacer/start-ui.mjs

参数说明

参数必填说明默认
-d, --dir <path>可选搜索目录，可重复指定；多个目录会逐个扫描后合并整个仓库根目录
--targets [path]可选按 targets.json 的 stages[].dirs + replaceOnly 提取；省略路径时用 name-replacer/targets.json；可与 -d 叠加关闭
--words-file <path>可选敏感词文件（JSON 数组或纯文本）base-words.json
--fused可选search-ec 启用融合词匹配（ECXML、ECSQLREADER）关闭
--input <path>可选直接使用已有的合并词表，跳过搜索和合并无
--skip-search可选跳过搜索，直接使用 all-ids.json关闭
-p, --port <n>可选配置网页端口3457
--no-open可选启动后不自动打开浏览器自动打开
bash · 常用组合
# 按 targets.json 的目录提取（多批次时推荐）
node name-replacer/start-ui.mjs --targets

# 只扫描指定目录
node name-replacer/start-ui.mjs -d ./szewtwinjs-core

# 复用已有 all-ids.json，不重新搜索
node name-replacer/start-ui.mjs --skip-search

# 换端口，且不自动开浏览器
node name-replacer/start-ui.mjs -p 3458 --no-open
一键启动只做到「配置映射」 保存映射、bim 替换、内容替换、构建发包都需要手动继续（见下面的完整流程）。 这样设计是为了让你在配置完映射后先检查、再动手。
所有脚本都支持 --help 例如 node name-replacer/search-ec.mjs --help。本页只列常用参数， 完整的默认值、边界行为以脚本 --help 和 README.md 为准。
02 · 完整流程

分步执行：每一步都能单独运行

正式替换建议按这个顺序走。下面每个阶段都包含：目的、命令、必要参数、输出文件和注意事项。

result.json敏感词提取结果（标识符按搜索词分组）
ec-result.jsonEC 提取结果（标识符列表 + 命中详情）
all-ids.json合并后的待配置词表，配置网页的输入
all-ids-mapping.json配置网页保存的替换映射（在 name-replacer/ 下）
name-mapping.jsonapply-replace 固定读取的映射表
第 1 步 · 准备

提交基线，准备 targets.json

替换会直接改磁盘上的源码。先保证有一个可回滚的基线。

bash
# 1) 确认工作区干净，提交或暂存当前改动
git status
git add -A
git commit -m "chore: 替换前基线"

# 2) 没有 targets.json 时，从示例复制一份
cp name-replacer/targets.example.json name-replacer/targets.json

# 3) targets.json 里按批次填写真实目录（见下）

targets.json 两种格式

json · 顶层数组
[
  { "dirs": ["base/units-schema"], "note": "第 1 批" },
  { "dirs": ["appui/ui/core-react"], "replaceOnly": ["appui/ui/appui-react"], "note": "第 2 批" }
]
json · 对象（可带 registry）
{
  "registry": "http://localhost:4873/",
  "stages": [
    { "dirs": ["base/units-schema"], "note": "第 1 批" }
  ]
}
字段说明
dirs替换内容并发布的目标目录（相对仓库根目录）
replaceOnly只替换内容、不发布；内容照样会提取 / 替换
registry发布目标；优先级：--registry > 这里 > 环境变量 > 默认 localhost
note批次说明，仅用于阅读
目录必须真实存在 不存在的目录会被明确提示并跳过；所有目标都不存在时，后续全局改名也不会执行。
第 2 步 · 提取

提取敏感词：search-sensitive

扫描源码，找出包含品牌词 / 产品词的标识符，输出 result.json。 默认扫描所有目录、所有扩展名，排除项由 scan-exclude.json 控制。

bash
node name-replacer/search-sensitive.mjs \
  -d . \
  --words-file base-words.json \
  --concise \
  -o result.json

必要参数

参数必填说明
-d, --dir <path>必填（推荐）搜索根目录；默认当前目录。正式流程一般显式写 -d . 或 targets 目录
--words-file <path>二选一从文件读取搜索词；JSON 数组 / {"words":[...]} / 纯文本均可，! 前缀 = 精确匹配
-w, --words <list>二选一逗号分隔的搜索词；词多时用文件更好维护
-o, --output <path>流程必填JSON 输出路径；正式流程必须写文件，供下一步合并
--concise建议只输出标识符和统计，不生成替换后文件

常用可选参数

参数说明
--whole-word只在标识符边界匹配（默认子串匹配）
--no-paths只搜文件内容，跳过目录名 / 文件名匹配
--ext <exts> / --ext-file <path>只扫描这些扩展名（白名单）
--include-ext / --include-dirs临时强制放行被 scan-exclude.json 排除的扩展名 / 目录
--protected-files <path> / --no-protected-files指定保护配置 / 临时关闭保护（见「保护机制」）
--context <n> / --limit-files <n>终端上下文长度 / 详情最多显示文件数
--json终端输出 JSON，不打印表格
怎么确认结果正常？ 终端会出现「词 × 文件」交叉表；stderr 会打印扫描文件数、匹配数、保护跳过数。 生成后打开 result.json 看 identifiers 是否只包含预期词。
第 3 步 · 提取

提取 EC：search-ec

把标识符按 camelCase / snake_case 分词，只提取 EC 作为独立语义 token 的标识符， 输出 ec-result.json。

bash
node name-replacer/search-ec.mjs \
  -d . \
  --concise \
  -o ec-result.json
参数必填说明
-d, --dir <path>必填（推荐）搜索根目录
-o, --output <path>流程必填输出 ec-result.json
--concise建议只输出标识符列表 + 计数
--fused可选融合词匹配：ECXML、ECSQLREADER、ecsqlreader 也会提取；DECLARE 这类英文单词也会混进来，提取 ≠ 替换
--case-sensitive可选大小写敏感（默认 Ec / ec / EC 都算）
--no-paths可选只搜内容，不报告目录名 / 文件名匹配
--ext / --include-ext / --include-dirs可选扩展名白名单 / 强制放行
--protected-files / --no-protected-files可选保护配置覆盖 / 临时关闭
匹配示例 ECEntityClass ✓、ECDb ✓、myEcSchema ✓、EC ✓； select ✗、AEC ✗、project ✗。
第 4 步 · 合并

合并词表：merge-ids

把多份搜索结果合并成一份 all-ids.json，作为配置网页的输入。

bash
node name-replacer/merge-ids.mjs ec-result.json result.json -o all-ids.json
参数必填说明
<file1.json> <file2.json> ...必填输入文件，可传任意多个；支持 identifiers 为数组或按词分组的对象
-o, --output <path>流程必填合并结果，默认 all-ids.json
输出检查 all-ids.json 里的 identifiers 应该是所有需要配置替换词的标识符全集； sources 会记录每份输入的标识符数和路径匹配数。
第 5 步 · 配置

配置映射：replace-server

在网页里为每个搜索词填写替换方案，保存后生成 name-replacer/all-ids-mapping.json，同时更新 replace-server-config.json。

bash
node name-replacer/replace-server.mjs --input all-ids.json
# 浏览器打开 http://localhost:3457
参数必填说明默认
--input <path>必填合并词表，通常是 all-ids.json无
-p, --port <n>可选网页端口3457
-w, --word <word>可选单词模式：只配置某个词多词模式
-o, --output <path>可选自定义映射表输出路径<input>-mapping.json
--config <path>可选自定义配置文件路径replace-server-config.json

网页里的操作顺序

1. 填替换词

逐词填写「基准替换词 / baseName」；按需开启融合词替换（ECXML 这类）。

2. 处理排除项

确认不能改的标识符加入排除列表；保存到 exclude-list.json。

3. 保存并更新映射

点击「保存并更新映射表」，整体生成 all-ids-mapping.json。

4. 检查产物

用「基础替换词保护」确认新词不会被二次改写，例如 szewEC_ECClass → szewEC_DMClass。

保存是整体覆盖，不是追加 需要保留旧映射时，先备份，或用 merge-mapping.mjs --into 合并。 手动确认 / 忽略结果保存在配置文件的 _manual / _manualTokens / _manualSkip。
第 6 步 · 可选

合并映射：merge-mapping

把新生成的映射并入已有的总表。默认合并 base-mapping.json + all-ids-mapping.json → 仓库根目录 all-mapping.json，后面的文件优先。

bash
# 默认：base-mapping.json + all-ids-mapping.json → all-mapping.json
node name-replacer/merge-mapping.mjs

# 任意多个文件，后面的优先
node name-replacer/merge-mapping.mjs base.json extra.json -o all-mapping.json

# 合并进已有总表，保留目标独有条目
node name-replacer/merge-mapping.mjs --into all-mapping.json base.json extra.json
参数必填说明
<file.json> ...可选输入映射；省略时用默认两份
-o, --output <path>可选输出路径，默认 all-mapping.json
--into <path>可选合并进已有文件，保留目标独有条目
第 7 步 · 替换前

bim 词族：replace-bim

只替换文件后缀 / 扩展名 / 格式字面量相关的 bim、ibim、bims， 不会动普通标识符和中文语境。必须在 replace-staged 之前运行， 否则构建发布的包里还是旧格式名。

bash
# 先预览
node name-replacer/replace-bim.mjs --dry-run --targets name-replacer/targets.json

# 确认后执行
node name-replacer/replace-bim.mjs --targets name-replacer/targets.json
参数必填说明
--dry-run强烈建议只预览改动，不写磁盘
--targets <file>二选一按 targets.json 的目录处理
--dir <dir>二选一直接指定目录，可重复
第 8 步 · 执行

执行替换：replace-staged / apply-replace

replace-staged 是完整流程：内容替换 → 目录改名 → 构建 → 发布 → 安装测试； apply-replace 只做内容替换和目录改名，不构建 / 不发布。

选择 A：分阶段替换（推荐，含发包与测试）

bash
# 1) 预览，不改磁盘、不构建
node name-replacer/replace-staged.mjs --targets name-replacer/targets.json --dry-run

# 2) 正式执行（替换 + 构建 + 发布 + 安装测试）
node name-replacer/replace-staged.mjs --targets name-replacer/targets.json

# 只替换，不安装 / 构建 / 发布 / 测试
node name-replacer/replace-staged.mjs --targets name-replacer/targets.json --replace-only

# 指定 registry（默认 http://localhost:4873/）
node name-replacer/replace-staged.mjs --targets name-replacer/targets.json \
  --registry http://192.168.1.10:4873/
参数必填说明
--targets <file>二选一按 targets.json 的批次执行
--dir <dir>二选一直接指定目录，可重复
--dry-run强烈建议预览，不修改、不构建、不发布
--replace-only可选只替换：不安装、不构建、不发布、不测试；不清空 rush.json、不改 .npmrc、不启动 Verdaccio
--no-install / --no-build可选跳过安装 / 构建
--no-publish / --no-test可选跳过发布 / 测试
--no-clear-rush可选不清空 rush.json（保留旧条目）
--registry <url>可选发布目标；优先级：参数 > targets.registry > 环境变量 > localhost

选择 B：只做内容替换（apply-replace）

bash
# apply-replace 固定读取 name-mapping.json
cp name-replacer/all-ids-mapping.json name-replacer/name-mapping.json

# 先预览
node name-replacer/apply-replace.mjs --targets --dry-run

# 执行（--targets 省略路径时用 name-replacer/targets.json）
node name-replacer/apply-replace.mjs --targets

# 也可以直接指定目录（可重复），不传时扫描整个仓库
node name-replacer/apply-replace.mjs --target appui --target base
参数必填说明
--target <dir>可选目标目录，可重复；与 --targets 叠加
--targets [file]可选从 targets.json 读取目录（dirs + replaceOnly）；省略路径用默认文件
--dry-run强烈建议预览，不改文件、不改目录名
这一步会真正改源码 确认前面的映射、保护配置、targets 批次都正确；确认已经 commit / stash。 中途失败先用 git diff 看清改动，再决定修复还是回滚。
第 9 步 · 收尾

验证与回滚

替换后重新提取一遍，对比标识符；检查构建产物、发包结果和测试。

bash
# 重新提取，确认品牌词已消失
node name-replacer/search-sensitive.mjs -d . --words-file base-words.json --concise -o result-after.json
node name-replacer/search-ec.mjs -d . --concise -o ec-after.json

# 看改了哪些文件 / 目录
git diff --stat
git status

# 需要回滚时
git checkout -- .
git clean -fd

检查提取结果

替换后 result-after.json 里不应再出现原品牌词；ec-after.json 中 EC 相关标识符应换成新词。

检查保护区域

保护文件 / 片段里原本的标识符应保持原样；保护只作用于提取阶段，替换保护用 exclude-list.json。

检查构建 / 发包

包名、依赖名、目录名、.bim → .dtw 等格式词都要核对；registry 上的版本是否正确。

检查测试

replace-staged 会跑安装测试；失败时看是源码替换问题还是依赖解析问题。

附录 A

保护机制：哪些词不能动

四套机制解决不同问题，别混用。

机制作用阶段粒度解决什么
scan-exclude.json扫描目录 / 扩展名 / 文件名根本不扫描：node_modules、dist、二进制、生成物
protected-words.json提取 + 生成映射标识符内部的一段区间已定稿的新词不被二次提取 / 改写（szewec 里的 ec）
protected-files.json提取整个文件 / 代码片段密码保护这类代码不能改名
exclude-list.json替换整个标识符 / 任意文本（可按路径）替换阶段跳过指定文本

基础替换词保护（自动生效）

自动来源：base-mapping.json 的所有值、replace-server-config.json 的 baseName、exclude-list.json 的全局条目； 需要补充时写 protected-words.json。提取时命中落在保护词内部就跳过； 生成映射时保护词先藏起来，避免被下一个词二次改写。

保护文件 / 保护片段（protected-files.json）

json · name-replacer/protected-files.json
{
  "files": [
    "szewtwinjs-core/core/backend/src/PasswordProtection.ts",
    { "path": "base/units-schema/src/license/", "note": "整目录保护" }
  ],
  "snippets": [
    "return {...from, baseUri: `${process.env.OBJECT_STORAGE_URL ?? \"http://10.0.19.202:9000\"}/${from.accountName}`, accessToken: from.sasToken, storageType: process.env.OBJECT_STORAGE_TYPE === \"minio\" ? \"minio\" : \"azure\" }"
  ]
}

files：整份文件

文件内容不参与提取；文件里的标识符在其他文件里也不再提取。

snippets：代码片段

直接贴代码原文，不需要逐字符一致。先收集片段里的候选标识符，再按当前搜索规则筛选：只有本来会被提取的词才排除。

片段保护的关键语义（培训重点） search-ec 只排除片段里带 EC 分词单元的标识符（如 sdfsEc54sdgsdf）； search-sensitive 只排除片段里命中当前搜索词的标识符。 片段里的 minio、azure、from、process 这类本来就不会被提取的词，不会进入保护名单。 被排除的标识符仍然全局生效（其他文件里的同名代码也不提取）。
bash · 查看保护区域
# 查看当前保护文件 / 片段概况
node name-replacer/protected-files.mjs

# 查看某个搜索词下，片段里实际会被排除的标识符（子串粗筛）
node name-replacer/protected-files.mjs --word EC

# 临时关闭保护
node name-replacer/search-ec.mjs -d . --no-protected-files

替换排除：exclude-list.json

json · name-replacer/exclude-list.json
[
  "CorEcA",
  { "text": "ECSecretKey", "paths": ["**/PasswordProtection.ts"] }
]

直接写字符串 = 全局生效；{ text, paths } = 只在匹配路径生效。 paths 相对 name-replacer/ 目录，支持 * / **。 该表在替换（apply-replace）阶段把文本藏成占位符，替换完再还原。

附录 B

配置文件速查

scan-exclude.json扫描排除：dirs / includeDirs / exts / files；搜索、替换共用
targets.json批次目录：stages[].dirs（替换+发布）、replaceOnly（只替换）
protected-words.json手工补充的基础替换词（自动来源之外）
protected-files.json保护文件 files + 保护片段 snippets（仅提取阶段）
exclude-list.json替换阶段排除文本；字符串全局，对象可按路径
base-mapping.json基础替换映射；其值会自动纳入基础替换词保护
replace-server-config.json配置网页的保存结果；baseName 自动纳入保护

scan-exclude.json 示例

常见问题

1. 提取结果为空 / 文件太少？

先看 stderr 的「目录 / 排除配置 / 扫描文件数」。常见原因：-d 指错目录； scan-exclude.json 排掉了目标目录；扩展名被白名单限制；词表文件路径不对。

2. 保护片段里明明有 minio / azure，为什么没进保护名单？

这是设计行为：保护片段只影响本来会被提取出来的词。 EC 提取不会命中 minio，敏感词搜索也不会（除非你的搜索词就是它）， 所以它们不需要保护。实际排除项会在搜索时打印在 stderr。

3. 保护配置生效了，为什么替换还是改了保护区域？

protected-files 只管提取阶段。已经存在于 base-mapping.json 的映射、或子串形式的替换仍可能改到它。需要替换也跳过时，用 exclude-list.json 的 { "text": "...", "paths": ["..."] }。

4. replace-server 保存后旧映射丢了？

保存是整体覆盖。保留旧条目的方式：先备份 all-ids-mapping.json， 或用 node name-replacer/merge-mapping.mjs --into 合并。

5. 多批次目录怎么安排？

按依赖顺序拆到 targets.json 的多个 stages； 只替换不发布的包放进 replaceOnly。批次划分可参考 name-replacer/dep-layers.md。

6. 发包目标怎么改？

优先级：--registry 参数 > targets 顶层 registry > 环境变量 REPLACE_STAGED_REGISTRY > 默认 http://localhost:4873/。

培训建议 第一次演示只走到 replace-server，让学员亲手保存一份映射； 第二次再用一个无关的小目录跑 apply-replace --dry-run 看替换预览； 最后才在真实批次上执行。
